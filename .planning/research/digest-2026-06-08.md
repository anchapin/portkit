## Papers Reviewed This Week (Jun 2–8, 2026)

### ≥80% Relevance — Issues Created

#### 1. CODEMENV: Benchmarking Large Language Models on Code Migration
- **ArXiv**: https://arxiv.org/abs/2506.00894
- **Date**: June 2025
- **Relevance**: 80%
- **Summary**: Benchmark for evaluating LLMs on code migration tasks — 922 examples across 19 Java/Python packages, covering 3 core tasks: incompatible function detection, function change detection, and environment adaptation. Average LLM pass@1 = 26.50%; GPT-4O tops at 43.84%. LLMs better at newer versions; exhibit logical inconsistencies identifying irrelevant changes.
- **PortKit Applicability**: PortKit's Java→Bedrock migration maps 1:1 to CODEMENV's 3 tasks. The 43.84% GPT-4O ceiling sets a baseline that MMSD fine-tuning should significantly exceed — but this has never been benchmarked. Dataset open-sourced.
- **Issue**: [#1726](https://github.com/anchapin/ModPorter-AI/issues/1726)

#### 2. Empirical Evaluation of LLMs for Migration of Code Fragments to Post-Quantum Cryptography
- **ArXiv**: https://arxiv.org/abs/2606.07341
- **Date**: June 5, 2026
- **Relevance**: 80%
- **Summary**: Fine-tuning LLMs on 800 paired code migration examples with category-specific functional test validation. Fine-tuned GPT-4.1-mini achieves 92.5% functional correctness vs. zero-shot baseline. Key finding: domain-specific fine-tuning is *essential* for reliable code migration. Limitation: larger projects with complex dependencies are harder.
- **PortKit Applicability**: Validates PortKit's MMSD fine-tuning approach (1400 pairs). Introduces category-specific functional test quality gate — a methodology PortKit's MMSD dataset currently lacks. The 92.5% target is achievable with proper dataset validation.
- **Issue**: [#1727](https://github.com/anchapin/ModPorter-AI/issues/1727)

### 65–79% Relevance (Horizon Notes)

#### 3. How Generation Architecture Shapes Code Complexity in Multi-Agent LLM Systems
- **ArXiv**: https://arxiv.org/abs/2606.00308
- **Date**: May 29, 2026
- **Relevance**: 75%
- **Summary**: Compares 6 multi-agent configurations (Basic, AC, ACT, Debugger variants) on 1,968 HumanEval tasks. Six architectures collapse into 2 complexity clusters (50–130% gap). Leanest architectures match or beat heaviest on accuracy. Analyst-coder split inflates complexity; debugger deflates it.
- **PortKit Horizon**: Directly applicable to PortKit's LangGraph pipeline audit. If the analyst-coder split adds complexity without accuracy benefit, simplifying the pipeline could reduce latency and token cost for the 60–80% "easy" mod conversions.

#### 4. From Agent Traces to Trust: Evidence Tracing and Execution Provenance in LLM Agents
- **ArXiv**: https://arxiv.org/abs/2606.04990
- **Date**: June 3, 2026
- **Relevance**: 75%
- **Summary**: Survey of evidence tracing and execution provenance methods for LLM agents. Covers how retrieved evidence, tool outputs, memory items, and intermediate claims connect to final outputs. Taxonomy of trace sources, evidence units, provenance relations, and trust functions.
- **PortKit Horizon**: PortKit's validator agent needs to trace *why* it accepted/rejected a conversion. Provenance-bearing validation (which retrieved API doc grounded this call? which trace step introduced this hallucination?) would improve debuggability and user-facing error reporting for B2B use.

#### 5. CodegenBench: Can LLMs Write Efficient Code Across Architectures?
- **ArXiv**: https://arxiv.org/abs/2606.04023
- **Date**: June 1, 2026
- **Relevance**: 70%
- **Summary**: Benchmark for LLM code generation across x86_64, Sunway, and Kunpeng. LLMs show significant degradation on domain-specific architectures with limited training data. Architecture-specific benchmarks reveal cross-platform generalization failures.
- **PortKit Horizon**: Reinforces why Bedrock Scripting API is hard — it's a low-resource target domain. The benchmarking methodology (architecture-specific evals) could be adapted to measure PortKit's Bedrock-specific performance separately from general Java code quality.

#### 6. Cross-Lingual Token Arbitrage: Optimizing Code Agent Context Windows via Local LLM Preprocessing
- **ArXiv**: https://arxiv.org/abs/2606.03618
- **Date**: June 2, 2026
- **Relevance**: 65%
- **Summary**: Pre-flight prompt rewriting middleware using a local 3B model. Reduces prompt tokens by 34–47% and total tokens by up to 18.8% while preserving task accuracy. Rewriting stage (not just function-name extraction) drives the gains.
- **PortKit Horizon**: For large Java mod files that push context windows, a lightweight pre-processing step that compresses Java source into compact task-oriented format before passing to the converter could reduce cost and latency. Phase 0.6 experiment candidate.
