### [2606.11863] Enhancing LLM-Based Code Translation with Verified Multi-Semantic Representations (Multisage)
- **arXiv:** https://arxiv.org/abs/2606.11863
- **Submitted:** June 2026 · cs.SE
- **Relevance:** 85% — code_translation
- **GitHub Issue:** [#1866](https://github.com/anchapin/portkit/issues/1866) — *Adopt Multisage Multi-Semantic Augmentation and Self-Calibration for Java-to-Bedrock Translation*

**Summary:** Multisage targets LLM code translation's core weakness — reliance on token-level statistical patterns rather than genuine program-semantic understanding, which produces translations that compile but behave incorrectly. Three modules: (1) Semantic Representation Parsing extracts data-flow graphs, type constraints, and external API info from source; (2) Multi-Semantic Augmentation generates code summaries, function-level test cases, and API-oriented descriptions from those base semantics; (3) Semantic Consistency Calibration uses semantics-preserving mutations plus cross-semantic consistency verification to filter and refine the generated semantics before they guide translation. Improves translation success rate on HumanEval-X over baselines lacking this scaffolding.

**PortKit applicability:** PortKit's Bedrock output can compile and pass schema validation yet still diverge behaviorally from the source Java mod — exactly the gap Multisage targets. Data-flow/type-constraint extraction gives the translator a structured semantic anchor (complements last week's deterministic-anchoring horizon note); external API-call manifests narrow Bedrock RAG retrieval (#1189) for API-heavy mods; semantics-preserving mutation testing is a new, cheap semantic-regression signal PortKit currently lacks; and Multisage's generated test-case sketches can seed #1857's auto-generated Bedrock unit tests with real behavioral assertions instead of compile/coverage-only signals. Strong synergy with #1189, #1268/#1857, #1856, #1721, #1090.

### [2607.00711] ClarifyCodeBench: Evaluating LLMs on Clarifying Ambiguous Requirements for Code Generation
- **arXiv:** https://arxiv.org/abs/2607.00711
- **Submitted:** July 1, 2026 · cs.SE
- **Relevance:** 70% — multi_agent_qa / code_llm_benchmarks

**Summary:** Interactive benchmark for evaluating whether LLMs proactively clarify ambiguous/underspecified requirements rather than silently guessing. Introduces Turn-discounted Key Question Rate and Optimal Round Adherence metrics. Key finding — the "Reasoning Paradox": increased computational thinking improves code correctness but yields only marginal gains in identifying ambiguity. Also finds capability decoupling: strong code generation does not imply effective clarification behavior.

**PortKit horizon:** Directly relevant to the B2B "guided conversion" tier proposed in #1856 — when a Java mod feature has no clean Bedrock equivalent (a genuinely ambiguous translation target, not just a bug), the pipeline should surface a clarifying question to the mod owner rather than silently guessing or stubbing. The Reasoning Paradox finding means simply using a stronger/reasoning model won't solve this — PortKit would need an explicit ambiguity-detection step (likely paired with the icat-agent rubric-based quality routing from last week's horizon note) rather than relying on model capability alone.

### [2607.00692] Self-GC: Self-Governing Context for Long-Horizon LLM Agents
- **arXiv:** https://arxiv.org/abs/2607.00692
- **Submitted:** July 1, 2026 · cs.SE / cs.AI
- **Relevance:** 70% — multi_agent_qa

**Summary:** Context-lifecycle management for long-horizon agents: treats tool results, files, plans, and constraints as indexed objects rather than a disposable text suffix, using a side-channel planner to propose fold/mask/prune actions with recoverable sidecars. On a 33-session hard set, prunes 43.95% of prefix tokens while leaving 84.85% of future continuations unaffected (vs. 54.55–69.70% no-impact rate for heuristic baselines). Production deployment: 10–20% reduction in daytime input tokens.

**PortKit horizon:** PortKit's LangGraph pipeline accumulates substantial context across a single large-mod translation run — Java source, Bedrock RAG results (#1189), intermediate translations across milestones (#1856), and repair-loop history (#1268/#1857). As mods scale to 50k+ LOC and milestone decomposition adds more pipeline stages, naive context accumulation becomes a real cost/latency driver. Self-GC's object-lifecycle approach (rather than chronological pruning or final summarization) is a general infra improvement worth a follow-up cost audit once #1856's milestone pipeline is in production — not yet PortKit-specific enough for an issue on its own.
