## Papers Scored ≥80% (Issue-Worthy)

### 1. Multisage: Enhancing LLM-Based Code Translation with Verified Multi-Semantic Representations
- **arXiv:** [2606.11863](https://arxiv.org/abs/2606.11863)
- **Relevance:** 90% — code_translation
- **Issue:** [#1738](https://github.com/anchapin/portkit/issues/1738)

**Summary:** Multi-semantic augmentation + self-calibration framework for LLM code translation. Key finding: 70–90% of translation failures are *intervenable semantic errors* (API misuse, dependency/logical errors, type mismatches) — not model capacity limits. Three modules: (1) Semantic Representation Parsing — AST/CFG analysis, type constraint extraction, API dependency extraction; (2) Multi-Semantic Augmentation — function summaries, API usage descriptions, LLM-generated execution-validated test cases; (3) Semantic Consistency Calibration — semantics-preserving mutations + cross-semantic verification to filter unreliable signals. **Results: up to 2.22× improvement in translation success rate on HumanEval-X; consistent gains across all model sizes.**

**PortKit application:** Directly addresses the primary failure mode in Java→Bedrock conversion (Bedrock API hallucination). Pre-translation semantic extraction of Minecraft Forge/Fabric API call sites + Bedrock API KB lookup + post-generation calibration against extracted semantic views.

### 2. Systematic LLM Translation of Legacy Scientific Code to Differentiable Frameworks
- **arXiv:** [2606.07681](https://arxiv.org/abs/2606.07681)
- **Relevance:** 85% — code_translation
- **Issue:** [#1737](https://github.com/anchapin/portkit/issues/1737)

**Summary:** Five-phase LLM-based agentic pipeline for legacy Fortran→JAX translation. Evaluated on 73 module translation tasks (~19,000 tokens/translation). Phases: (1) Static Dependency Analysis — topological module translation ordering; (2) **Stub Generation** — type-safe interface stubs generated *before* full translation (key innovation); (3) LLM-Driven Translation with stub scaffolding; (4) Compilation-Driven Repair — iterative tsc-style error repair; (5) Numerical Validation — behavioral correctness check.

**PortKit application:** PortKit's pipeline is missing stub generation and dependency ordering. Stub generation locks in correct Bedrock API signatures before the LLM runs, eliminating a large category of API signature mismatch failures. Dependency ordering ensures leaf classes are translated first, preventing partial-translation dependency deadlocks.

## Papers Scored 65–79% (Horizon Notes)

### 3. Latent Reasoning Guidance for Parallel Code Translation
- **arXiv:** [2606.05518](https://arxiv.org/abs/2606.05518)
- **Relevance:** 75% — code_translation / prompt_optimization
- **Status:** Horizon note — not immediate issue

**Summary:** Test-time Process Reward Model (PRM) guidance for parallel API translation (HPC context — CUDA/OpenMP). Improves mean validation rate from 32.89% (unguided) to substantially higher on 76-task ParaTrans benchmark. No fine-tuning of main generator required. The PRM guides latent reasoning before code generation to steer toward API-semantically-correct outputs.

**PortKit horizon:** Test-time guidance without fine-tuning could steer PortKit's LLM toward Bedrock-correct API usage at inference time. Requires training a lightweight PRM on PortKit conversion outcomes — worthwhile after MMSD fine-tuning data is available.

### 4. FASE: Fast Adaptive Semantic Entropy for Code Quality
- **arXiv:** [2606.09800](https://arxiv.org/abs/2606.09800)
- **Relevance:** 70% — code_llm_benchmarks / multi_agent_qa
- **Status:** Horizon note — not immediate issue

**Summary:** Fast Adaptive Semantic Entropy (FASE) approximates functional correctness via minimum description length principles, replacing expensive LLM-based semantic equivalence checks in multi-agent code generation settings. Practical, cost-effective uncertainty quantification that scales to production multi-agent pipelines.

**PortKit horizon:** FASE's uncertainty metric could serve as a fast conversion confidence signal in PortKit's pipeline — flag low-confidence conversions for human review before they reach the eval step. Relevant to Phase 0.7 B2B transparency (related to per-segment confidence scoring from issue #1091).
