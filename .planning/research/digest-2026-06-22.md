### [2606.17683] SwiftTrans: Bridging Functional Correctness and Runtime Efficiency Gaps in LLM-Based Code Translation
- **arXiv:** https://arxiv.org/abs/2606.17683
- **Submitted:** June 16, 2026
- **Relevance:** 90% — code_translation
- **GitHub Issue:** [#1765](https://github.com/anchapin/portkit/issues/1765) — *Adopt SwiftTrans Dual-Stage Strategy for Runtime-Efficient Bedrock Code Generation*

**Summary:** SwiftTrans proposes a two-stage LLM code translation framework. Stage 1 (MpTranslator) generates diverse translation candidates in parallel using in-context learning with Hierarchical Guidance. Stage 2 (DiffSelector) picks the best candidate via Ordinal Guidance that explicitly compares candidate differences. Key empirical finding: LLM-translated code is consistently slower than human-written code, and prompt engineering alone cannot fix this. Benchmarks (CodeNet, F2SBench, new SwiftBench) show SwiftTrans improves both correctness and runtime efficiency.

**PortKit applicability:** Bedrock JavaScript runs in a tick-constrained scripting environment — efficiency is a commercial-grade quality gate. MpTranslator's parallel candidate generation maps directly to PortKit's LangGraph multi-agent pipeline. DiffSelector's comparative ranking extends the rubric-grounded evaluator (#1367) with an efficiency dimension. Also informs MMSD fine-tuning: label training pairs by efficiency tier, prefer idiomatic low-allocation Bedrock code in training data.

### [2606.08840] Beyond Pass Rate: A Multilingual, Execution-Grounded Evaluation of Open Code LLMs
- **arXiv:** https://arxiv.org/abs/2606.08840
- **Submitted:** June 7, 2026
- **Relevance:** 75% — code_llm_benchmarks

**Summary:** Large-scale evaluation of 9 open code LLMs on 2,707 LeetCode problems across 12 programming languages (325K total jobs). Key findings: (1) best open model reaches only 23.64% correctness vs 57.2% human baseline, (2) compile errors cause 63.25% of failures — semantic correctness is rarely even tested because code doesn't compile, (3) rankings are language/difficulty-dependent (Qwen2.5-Coder-14B best on hard problems; Gemma-2-27B best on lint pass rate).

**PortKit horizon:** The 63.25% compile-error failure rate mirrors PortKit's Bedrock schema validation failures — most Bedrock conversion failures likely occur before semantic quality can be assessed. Strengthens the case for #1268 (contract-repair loop) as a high-ROI issue: a fast compile-time check before semantic evaluation filters most failures cheaply. Also informs MMSD model selection: Qwen2.5-Coder-14B shows strongest performance on hard/complex problems, which maps to complex Java mod translation scenarios.
